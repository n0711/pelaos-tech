# PELAOS — software projects & research

Existing publication: **https://n0711.github.io/pelaos-tech/** (GitHub Pages).

**Vercel support is prepared:** the repository includes a static-site build and root-path deployment settings. A production Vercel URL has not yet been verified or recorded here. RioTuner's product, testing and privacy pages are generated by this site; the Android application is built in its separate repository.

| Part | Language | Role |
|---|---|---|
| `src/` | Rust | Renders every page to complete HTML at build time: content, layout, JSON-LD, sitemap. The deployed site serves static files. |
| `web/app.dart` | Dart | Compiled to `app.js`. Adds the 0–500 m depth calculator on /research/, in 1 m steps. Pages work fully without it. |
| `.github/workflows/pages.yml` | | Tests and builds pull requests; deploys on every push to `main`. |
| `vercel.json`, `scripts/build-vercel.sh` | Bash | Builds the same site for Vercel, with root-path links and production canonical URLs. |

## Pages

- `/`: project portfolio with RioTuner, cysk8clips, Narrify, LearnTwin and VERA-MOT
- `/cultural-storytelling-map/`: Narrify team credits, source repository and a sourced place-name pilot
- `/research/`: 0–500 m depth meter, seawater gauge pressure and viewport force, ROV vs AUV, navigation without GPS (NOAA sources). The meter is a calculator, not connected to a pressure sensor. Its range and initial depth are passed from Rust to Dart through data attributes.
- `/riotuner/`: Google Play release in preparation, with synthetic benchmark results
- `/riotuner/testing/`: release status, physical-device testing preparation and useful feedback
- `/riotuner/privacy/`: RioTuner privacy policy (the URL to enter in Google Play Console)
- `/privacy/`: website privacy, with a disclosure for the selected hosting provider

Paths are relative to the site base: GitHub Pages adds `/pelaos-tech`; Vercel serves them from `/`.

## Deploy with Vercel

Import **`n0711/pelaos-tech`**, with repository root `.` as the project root. The committed configuration selects:

- Framework preset: **Other** (`framework: null`)
- Build command: **`bash scripts/build-vercel.sh`**
- Output directory: **`dist`**
- Directory URLs with trailing slashes

Enable Vercel system environment variables. The script uses `VERCEL_PROJECT_PRODUCTION_URL` for canonical URLs, including in preview builds. To choose an explicit production or custom domain, set **`PELAOS_SITE_URL`** to its HTTPS origin without a trailing slash. The script sets an empty base path and the Vercel hosting disclosure automatically.

The build installs a minimal stable Rust toolchain if Cargo is absent and uses Dart 3.13.5, downloading and checksum-verifying the SDK when needed. It runs Rust tests, renders the pages, analyzes Dart and compiles the browser enhancement before producing `dist/`.

See [deployment and URL verification](docs/DEPLOYMENT.md) before replacing the existing published links. Vercel publishes the website; it does not build or release an Android APK.

## Build locally

Needs a stable Rust toolchain and the Dart SDK 3.5 or newer. Neither the Rust
generator nor the Dart script pulls in third-party packages.

```powershell
cargo test
cargo run -- dist
dart pub get
dart analyze --fatal-infos web/app.dart
dart compile js -O2 --csp -o dist/app.js web/app.dart
```

Pull requests run the Rust tests, render the site, analyze the Dart enhancement
(including informational diagnostics), and compile it before deployment is eligible.
Only pushes to `main` and manually triggered workflows deploy through GitHub Pages. The Pages workflow retains its existing behaviour; Vercel uses its own build and deployment status.

With no deployment environment overrides, local builds produce GitHub Pages URLs. On Linux, set `PELAOS_SITE_URL` to the intended HTTPS production origin and run `bash scripts/build-vercel.sh` to build with Vercel's root-path settings.

### Output directory safety

The Rust generator accepts a new or empty output directory. Later builds replace
that directory only when it contains the generator's `.pelaos-site-output` marker.
The whole marked directory is generated output; keep source files elsewhere and
do not add the marker manually. Symbolic links and `..` in output paths are rejected.
A complete build is staged before the previous build is replaced.

An older, unmarked `dist` is deliberately refused. Use a fresh output path (for
example `cargo run -- dist-new`), or inspect and manually remove the old generated
directory before rebuilding. Never use the repository or a source directory as output.

## Moving to a custom domain

Set `PELAOS_SITE_URL` to the verified HTTPS production origin and `PELAOS_BASE_PATH` to an empty string before compiling the generator. On Vercel, configure the domain in the project and rebuild; its build script sets the empty base path. For a GitHub Pages custom domain, also add the appropriate `CNAME` to the output and configure Pages settings. `robots.txt` and `llms.txt` are served at the domain root on root-path deployments. Do not publish an unverified domain as a live link.

## RioTuner release status

RioTuner remains **pre-release**. Synthetic benchmark results establish algorithm behaviour on generated signals; they do not establish physical-phone accuracy. An installable APK, documented phone sessions and Google Play availability must be verified separately before changing the public release status.
