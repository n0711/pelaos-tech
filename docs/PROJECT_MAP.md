# PELAOS project map
26 October 2026 | Draft v0.1 | Proposed organisation for review

PELAOS is the proposed umbrella for software services, the project portfolio and OpenPELAOS research. This records an organisational proposal. It does not assert incorporation, income, ownership of collaborators' work or adoption of this charter.

## Public project structure

| Strand / project | Audience and purpose | Recorded evidence | Next gate |
| --- | --- | --- | --- |
| PELAOS website service | One small business needing a bounded informational website | Existing service-first decision record and a one-page pilot offer; price and customer demand remain hypotheses [P2], [P3] | Review one buyer/problem hypothesis and rehearse delivery using a fictional brief; record effort |
| PELAOS portfolio | Visitors assessing software and research work | Rust static-site generation, Dart enhancement and an existing GitHub Pages publication are described in the README; Vercel production URL is not yet verified there [P1] | Keep availability statements attached to a dated source and a verified URL |
| OpenPELAOS | People examining or contributing to civilian software and research | The name already appears in ROS3-Limassol and Narrify integration records; the linked charter supplies a proposed common scope [P1], [R1] | Review mission, included projects, attribution and per-artefact permissions |
| ROS3-Limassol under OpenPELAOS | Civilian robotics researchers examining telemetry arrival-liveness | Python core, optional Humble/Jazzy adapters, recording/replay, offline evidence and an experimental Rust core are documented; physical validation remains pending [R1] | Reproduce a bounded synthetic result with its revision/environment, then evaluate bench or field observations separately |
| Other portfolio references | Users of LearnTwin, cysk8clips, RioTuner, Narrify and VERA-MOT | These projects are listed in the portfolio README; this planning change does not re-audit their releases [P1] | Retain each project's own collaborators, source, licence and evidence record |

Linking a project does not transfer ownership, adopt the charter for its contributors or change permissions.

## Proposed priorities

1. Preserve the website-service priority already recorded in [PRODUCT_DECISIONS.md](PRODUCT_DECISIONS.md).
2. Use ROS3-Limassol as the first research project covered by the [charter draft](OPENPELAOS_CHARTER.md).
3. Give each active experiment one bounded deliverable and a named next evidence gate.
4. Add features or migrations when an observed constraint or research question justifies them.

Buyer/segment selection, final programme scope and charter adoption remain open. No customer agreement, payment or field-performance claim is recorded by this draft.
